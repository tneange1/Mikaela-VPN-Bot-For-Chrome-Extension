# Mikaela Chrome-proxy bot

Telegram-бот, который по одной команде превращает сервер в HTTPS-прокси для расширения Mikaela VPN.
**С панелью Remnawave не связан**: прокси — отдельный контейнер Xray (`mikaela-proxy`), ноды не трогаются.

## Что делает добавление сервера
1. Заходит на сервер по SSH (ключ хоста запоминается при первом подключении и дальше проверяется).
2. Если сертификата нет или он на исходе (<30 дней):
   - находит всё, что слушает порт 80 (docker-контейнеры и systemd-службы), **останавливает**,
   - выпускает сертификат Let's Encrypt (certbot standalone),
   - **возвращает всё обратно** — даже если выпуск упал. Состояние пишется на сервер в `/var/lib/mikaela-bot/paused.json`, поэтому при аварии бота есть `/restore`.
   - Если порт 80 держит что-то, что нельзя гарантированно вернуть (не docker и не systemd) — бот **ничего не трогает** и сообщает.
3. Берёт свободный порт (по умолчанию 9443–9499, проверяет TCP и UDP на всех нодах сервера) и запускает прокси.
4. Открывает порт в `ufw`, если он включён.
5. Проверяет «снаружи» (с машины бота): валидный сертификат, логин, выход в интернет.
6. Только после успешной проверки дописывает сервер в `servers.json` в GitHub — расширение подхватит сам.

Раз в 12 часов бот сам проверяет сертификаты и продлевает за 30 дней до конца (с уведомлением).

## Установка (Docker)
Бот работает в отдельном контейнере `mikaela-bot` со своим compose-проектом, сетью и томом. Порты наружу не
публикуются, ресурсы ограничены (256 МБ, 0.5 CPU), Remnawave и другие контейнеры не затрагиваются.

```bash
git clone https://github.com/tneange1/Mikaela-VPN-Bot-For-Chrome-Extension /opt/mikaela-bot
cd /opt/mikaela-bot
cp .env.example .env && chmod 600 .env && nano .env
docker compose up -d --build
docker logs -f mikaela-bot          # смотреть логи (Ctrl+C — выйти)
```
В `.env` нужны: токен от @BotFather, ваш Telegram ID (@userinfobot), fine-grained токен GitHub только на
Mikaela-VPN-Chrome-Extension (Contents: Read and write), пароль прокси, e-mail для Let's Encrypt. SSH-ключ бот создаёт сам.
Дальше бот управляется кнопками: напишите ему `/start`.

## Автообновление
Код бота лежит в томе и тянется из этого репозитория (ветка `main`). Раз в 10 минут бот проверяет git; если вышел новый
коммит и автообновление включено (⚙️ Обновление), он ждёт конца текущих операций, пишет вам и перезапускается.
- Если новая версия не запустилась (упала в первые 40 секунд или не поставились зависимости), бот **откатывается**
  на прежнюю, запоминает плохой коммит и пишет об этом. Следующий коммит снова попробует.
- Образ пересобирать нужно редко: только если менялись `Dockerfile`, `entrypoint.sh` или `docker-compose.yml`
  (`cd /opt/mikaela-bot && git pull && docker compose up -d --build`).
- При `docker stop`/перезапуске контейнера бот даёт до 60 секунд на завершение начатой операции, а после старта сам
  возвращает всё, что могло остаться остановленным на порту 80.

## Серверы с Remnawave
Если добавляете сервер, на котором стоит панель, для сертификата порт 80 освобождается на ~30 секунд. Перед этим бот
**всегда спрашивает кнопкой**, что именно остановит (например, reverse-proxy панели), и без разрешения ничего не
трогает. Автопродление тоже спрашивает; чтобы оно шло без вопросов, поставьте `AUTO_PAUSE=1`.
Сам прокси (`mikaela-proxy`) занимает отдельный свободный порт и ноды Remnawave не касается.

## Добавление сервера
Кнопка **➕ Добавить сервер** спрашивает по шагам:
1. домен (`fi.mikaelavpn.xyz`);
2. IP для SSH (можно `1.2.3.4:2222`; «-», если домен уже указывает на сервер);
3. как заходить: **пароль root** (бот войдёт один раз, поставит на сервер свой ключ, пароль нигде не хранится),
   **загрузить свой SSH-ключ** (текстом или файлом) или **ключ бота** (его публичная часть в «🔑 SSH-ключ»);
4. название и код страны (`Финляндия FI`) или «Пропустить».

Сообщения с паролем и ключом бот сразу удаляет из чата. Публичный ключ загружать не нужно, он вычисляется из приватного.
Остальное тоже кнопками: **📋 Серверы** → сервер → продлить / перевыпустить сертификат / вернуть остановленное на :80 /
удалить; **🩺 Статус**; **🔑 SSH-ключ** (в том числе загрузка своего приватного ключа); **⚙️ Обновление**.

На сервере нужны docker и домен с A-записью на сервер (без проксирования CDN). Порт 80 должен быть открыт из интернета,
выбранный порт прокси (бот его назовёт) открыт в файрволе хостера. Для входа по паролю на сервере должен быть разрешён
root-вход (`PermitRootLogin yes`).

## Безопасность
- Бот отвечает только `ADMIN_IDS`.
- У бота root-доступ ко всем серверам: ключ лежит в `data/ssh/` (права 600), `.env` тоже 600. Не запускайте бота в общедоступном месте.
- Чат с ботом — приватный: пароль и ключ вы присылаете сюда, бот удаляет сообщение, но в Telegram оно уже проходило.
- `PROXY_USER/PROXY_PASS` публикуются в `servers.json` и внутри расширения — считайте их публичными.
  Прокси блокирует локальные адреса, торренты и SMTP (25/465/587).
- Лимиты Let's Encrypt: 5 неудачных выпусков в час на домен — не жмите «Добавить» повторно при ошибке DNS.

## Тесты
`python3 tests/test_logic.py` — останов/возврат процессов, SSH, GitHub; `python3 tests/test_ui.py` — кнопки и мастер на поддельном Telegram;
`python3 tests/test_entrypoint.py` — самообновление, откат битого коммита, остановка по SIGTERM.
Реальный certbot и сборка образа в тестах не запускались — первое добавление сервера делайте на запасном сервере.
